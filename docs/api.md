# API

Full interactive documentation (auto-generated by FastAPI from the Pydantic
schemas in `backend/app/schemas/schemas.py`) is always available at
**http://localhost:8000/docs** while the backend is running -- that page is
the authoritative reference; this document explains the *shape and intent*
of each endpoint for readers who don't have the server running in front of
them.

Every endpoint is under the `/api` prefix. All responses are JSON.

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/health` | Liveness check + whether the optional semantic layer loaded |
| `GET` | `/api/languages` | Every language the platform knows about (active + planned) |
| `POST` | `/api/translations` | Run the hybrid pipeline on one phrase (the core endpoint) |
| `GET` | `/api/translations/search` | Paginated, filterable dictionary search |
| `GET` | `/api/translations/categories` | Distinct category values, for search/flashcard filters |
| `GET` | `/api/dataset/stats` | Per-language dataset stats + category breakdown |
| `GET` | `/api/curriculum/grades` | Grade → Subject → Chapter tree |
| `GET` | `/api/curriculum/chapters/{id}` | One chapter's content units |
| `GET` | `/api/flashcards/categories` | Categories available as flashcard decks |
| `GET` | `/api/flashcards/deck` | One category's cards |
| `POST` | `/api/feedback` | Submit free-text feedback (+ optional 1-5 rating) |

## `POST /api/translations`

```json
// Request
{ "text": "आप कैसे हैं?", "source_language": "hi", "target_language": "mundari" }
```

```json
// Response (truncated)
{
  "input_text": "आप कैसे हैं?",
  "result_text": "आम चिलेका मेना मा?",
  "method": "exact",
  "confidence": 1.0,
  "confidence_label": "high",
  "verified": true,
  "ai_assisted": false,
  "message": "Exact match found in the verified dataset.",
  "alternatives": []
}
```

`method` is one of `exact | normalized | fuzzy | semantic |
external_bhashini | none` -- see `docs/ai-pipeline.md` for exactly what
produces each. `result_text` is `null` (never a guessed string) when
`method` is `"none"`.

## Error shape

Every error -- validation failure, 404, unhandled exception -- returns
`{"detail": "..."}` with an appropriate status code. Unhandled exceptions
are logged server-side with a full traceback (`app/main.py`'s
`unhandled_exception_handler`) but the client only ever sees a generic
"An unexpected error occurred" message, per the "don't expose stack traces"
requirement.

## Rate limiting

A per-IP fixed-window limiter (`app/core/rate_limit.py`) returns `429` past
`RATE_LIMIT_PER_MINUTE` requests/minute (default 120). It is in-memory and
intentionally simple -- see `docs/limitations.md`.

## Why hand-written schemas instead of generated client code

The frontend's `src/types/index.ts` mirrors `backend/app/schemas/schemas.py`
by hand rather than via an OpenAPI codegen step. For a project this size,
adding a codegen pipeline (and keeping it running in CI) would cost more
setup time than it saves, and the two files are small enough that a
mismatch is caught immediately by TypeScript's structural typing the first
time a component tries to read a field that doesn't exist. A larger,
multi-team version of this project would be a good candidate for
`openapi-typescript` instead.
